# LiCai｜一人智能理财工作台

LiCai 将研究、数据与决策整理成可复核的工作流。每份决策方案、代码或数据在进入执行层前，都要经过独立反调审查。

## 工作流

`任务要求 → 研究与数据 → 决策方案 → 反调审查 → 决策层异议/裁决 → 执行`

- **决策智能体**：提出方案或产物，并交代依据、假设、验证和限制。
- **反调审查者**：找出问题，按“问题 + 解决方案”逐条提交证据与整改要求；不直接修改被审产物。
- **决策层**：核查反调证据；可以驳回判断并要求针对性复核。
- **执行层**：只接收在明确范围内通过审查、且没有任何未解决问题或待核验关键项的产物。

审查通过不等于证明“绝无 bug”或“零风险”。结论必须列出检查范围和未覆盖部分。没有来源、证据或验证结果时，应标为待核验；不能用格式检查代替事实核验。

## 仓库规则

- 先读 [AGENTS.md](AGENTS.md) 与 [审查门禁](docs/review-gate.md)。
- 数据的来源、时间、单位、口径和转换见 [数据溯源规范](docs/data-provenance.md)。
- 研究能力与适用范围见 [工作流目录](docs/operating-workflows.md)。
- 通过 Pull Request 交付审查规则；[PR 模板](.github/PULL_REQUEST_TEMPLATE.md)要求提交范围、证据、验证和风险说明。
- [CODEOWNERS](.github/CODEOWNERS) 标记仓库所有者为代码审查责任人。GitHub 分支保护仍需在仓库设置中启用并核实；仅有此文件不能阻止合并。

## 范围

当前仓库先建立研究、数据核验与交接治理。此仓库未获授权接入券商账户或自动下单。投资信息用于分析与审查，不构成收益承诺。
